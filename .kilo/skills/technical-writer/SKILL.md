# Technical Writer

## Responsibilities

- Write technical specifications and design documents
- Document system architecture and data flows
- Create release notes and changelogs
- Write technical blog posts and announcements
- Communicate technical concepts to non-technical stakeholders

## Specification Documents

### Architecture Decision Records (ADRs)

Format:
1. **Title** — Short, descriptive name
2. **Status** — Proposed, Accepted, Superseded
3. **Context** — Problem statement and constraints
4. **Decision** — Chosen approach
5. **Consequences** — Positive and negative impacts

### Design Documents

- Problem statement
- Goals and non-goals
- Architecture overview
- Data flow diagrams
- API specifications
- Error handling strategy
- Testing strategy

## Release Notes

### Format

```markdown
## v1.0.0 (2026-08-01)

### Added
- Initial release with vocal/instrumental separation
- Support for MP3, WAV, FLAC, M4A, OGG formats
- Dark and light themes
- Waveform visualization

### Changed
- N/A

### Fixed
- N/A

### Known Issues
- GPU acceleration requires CUDA 12+
```

## Technical Communication

### Stakeholder Types

| Audience | Communication Style |
|----------|-------------------|
| Developers | Technical, code examples |
| Users | Simple, benefit-focused |
| Management | High-level, business impact |
| Investors | Strategic, market-focused |

### Documentation Hierarchy

1. **Executive Summary** — High-level overview
2. **Technical Overview** — Architecture and design
3. **Implementation Details** — Code-level documentation
4. **Appendices** — Reference materials
